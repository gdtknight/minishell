# 04. 파일 디스크립터

## 파일 디스크립터란

**파일 디스크립터(file descriptor, fd)** 는 프로세스가 연 파일·파이프·소켓·터미널 등을 가리키는 **작은 음이 아닌 정수**입니다. 커널이 프로세스마다 유지하는 테이블의 인덱스입니다.

```
프로세스 A의 fd 테이블         커널의 열린 파일 테이블
┌─────┬────────────┐          ┌────────────────────┐
│  0  │  ───────────┼────────→│ /dev/tty (stdin)   │
│  1  │  ───────────┼────────→│ /dev/tty (stdout)  │
│  2  │  ───────────┼────────→│ /dev/tty (stderr)  │
│  3  │  ───────────┼────────→│ /home/u/file.txt   │
│ ... │            │          │                    │
└─────┴────────────┘          └────────────────────┘
```

프로세스는 **정수**만 다루면 됩니다. 실제 어떤 객체를 가리키는지는 커널이 관리합니다.

## 표준 파일 디스크립터

모든 프로세스는 시작 시 다음 세 fd를 열어둔 상태로 시작합니다.

| fd | 매크로 | 용도 |
|----|--------|------|
| 0  | `STDIN_FILENO`  | 표준 입력 |
| 1  | `STDOUT_FILENO` | 표준 출력 |
| 2  | `STDERR_FILENO` | 표준 에러 |

```c
#include <unistd.h>

write(STDOUT_FILENO, "hello\n", 6);
write(STDERR_FILENO, "error\n", 6);
```

새로 열리는 fd는 **사용 중이지 않은 가장 작은 번호**를 얻습니다. 이 규칙이 `dup2` 트릭에서 중요하게 쓰입니다.

## 주요 시스템 콜

### `open(2)` — 파일 열기

```c
#include <fcntl.h>
int	open(const char *pathname, int flags, mode_t mode);
```

새 fd를 할당해서 파일을 연다. 실패 시 `-1`, `errno` 설정.

#### 주요 `flags`

| 플래그 | 의미 |
|--------|------|
| `O_RDONLY` | 읽기 전용 |
| `O_WRONLY` | 쓰기 전용 |
| `O_RDWR`   | 읽기·쓰기 |
| `O_CREAT`  | 없으면 생성(이때 `mode` 인자 필요) |
| `O_TRUNC`  | 열 때 파일을 비움 (`>` 리다이렉션에 사용) |
| `O_APPEND` | 매번 끝에 덧붙임 (`>>` 에 사용) |
| `O_EXCL`   | `O_CREAT` 와 함께: 이미 있으면 실패 |
| `O_NONBLOCK` | 논블로킹 모드 |

#### `mode` (파일 생성 시 권한)

팔진수(`0644`, `0666`) 또는 매크로(`S_IRUSR | S_IWUSR | ...`). 실제 권한은 `mode & ~umask`.

#### 리다이렉션 매핑

```c
/* > file   덮어쓰기 */
fd = open(file, O_WRONLY | O_CREAT | O_TRUNC, 0644);

/* >> file  이어쓰기 */
fd = open(file, O_WRONLY | O_CREAT | O_APPEND, 0644);

/* < file   읽기 */
fd = open(file, O_RDONLY);
```

### `close(2)` — fd 해제

```c
int	close(int fd);
```

**열었으면 반드시 닫기.** fd는 유한 자원(기본 1024개 내외).

### `read(2)` / `write(2)` — 입출력

```c
ssize_t	read(int fd, void *buf, size_t count);
ssize_t	write(int fd, const void *buf, size_t count);
```

- 성공 시 실제로 처리한 바이트 수 리턴(요청한 `count` 보다 적을 수 있음 — "short read/write").
- `read` 가 `0` 리턴하면 **EOF**.
- 실패 시 `-1`, `errno` 설정.

**주의**: 짧은 read/write는 파이프와 소켓에서 특히 흔합니다. 루프를 돌려야 할 수도 있지만, 셸 구현에서는 터미널·파일이 대상이라 대부분 문제 없음.

### `access(2)` — 파일 접근 가능 여부

```c
int	access(const char *pathname, int mode);
```

`mode` 는 `F_OK`(존재), `R_OK`(읽기), `W_OK`(쓰기), `X_OK`(실행) 의 OR. 성공 0, 실패 -1.

```c
if (access("/bin/ls", X_OK) == 0)
    /* 실행 가능 */;
```

PATH 검색에서 `X_OK` 를 자주 씁니다. [13. PATH 검색과 실행](13-PATH-검색과-실행).

### `dup(2)` / `dup2(2)` — fd 복제

셸 구현에서 가장 중요한 시스템 콜 중 하나.

```c
int	dup(int oldfd);             /* 가장 작은 빈 번호로 복제 */
int	dup2(int oldfd, int newfd); /* newfd 로 복제 (newfd가 열려있으면 먼저 닫음) */
```

- `dup` 은 `oldfd` 를 새 fd로 복제해서 **같은 파일을 가리키도록** 함.
- `dup2(oldfd, newfd)` 는:
  1. `newfd` 가 열려 있으면 **자동으로 close** 하고,
  2. `newfd` 가 `oldfd` 와 같은 파일을 가리키게 만듦.
  3. `oldfd == newfd` 이면 아무 것도 안 함(에러 아님).

### `dup2` 로 리다이렉션 구현

`> file` 을 구현한다고 해보자. 목표: `STDOUT_FILENO`(fd 1)이 `file` 을 가리키게.

```c
int fd = open(file, O_WRONLY | O_CREAT | O_TRUNC, 0644);
if (fd == -1) { perror("open"); return -1; }

dup2(fd, STDOUT_FILENO);  /* fd 1 이 file을 가리키게 됨. 기존 stdout은 자동 close. */
close(fd);                /* 원본 fd는 이제 불필요 */

/* 이 이후 write(1, ...) 하면 file 에 쓰임 */
```

핵심:

1. `open` 으로 일단 아무 fd나 얻는다(3, 4, ...).
2. `dup2(fd, 1)` 로 **stdout을 파일로 덮어쓴다**.
3. 원본 `fd` 는 더 이상 필요 없으므로 닫는다.

왜 굳이 `close(fd)` 를 하는가? **누수를 방지하고**, 자식 프로세스에 넘길 때 필요없는 fd가 열려 있으면 혼란이 생기기 때문. 특히 파이프에서는 이게 데드락의 원인이 됩니다.

### `stat` 계열 — 파일 메타데이터

```c
#include <sys/stat.h>
int	stat(const char *path, struct stat *buf);
int	lstat(const char *path, struct stat *buf);  /* 심볼릭 링크 자체 */
int	fstat(int fd, struct stat *buf);
```

`struct stat` 에는 파일 크기, 타입, 권한, mtime 등이 들어 있습니다.

```c
struct stat st;
if (stat("/tmp", &st) == 0)
{
    if (S_ISDIR(st.st_mode))
        /* 디렉터리 */;
    if (S_ISREG(st.st_mode))
        /* 일반 파일 */;
}
```

minishell에서는 주로 `cd` 가 대상이 디렉터리인지 확인할 때, 리다이렉션 대상이 일반 파일인지 볼 때 등에 쓸 수 있습니다. 보통은 `open` 의 실패 `errno` 만으로도 충분.

### `getcwd` / `chdir`

```c
char	*getcwd(char *buf, size_t size);  /* 현재 작업 디렉터리 */
int	chdir(const char *path);          /* cwd 변경 */
```

`cd` 빌트인의 핵심. `chdir` 성공 후 `getcwd` 로 새 PWD 를 확인하고 환경 변수에 반영합니다.

## fork 와 fd

**fork 후 자식은 부모의 fd 테이블을 복제**합니다. 중요한 두 가지 속성:

1. **부모·자식의 fd는 같은 열린 파일을 가리킨다.** 오프셋·플래그가 공유됨.
2. **자식이 fd를 닫아도 부모의 fd는 유효.** 반대도 마찬가지.

`execve` 는 기본적으로 fd를 **유지**합니다. 닫고 싶다면 열 때 `O_CLOEXEC` 플래그를 주거나 `fcntl(fd, F_SETFD, FD_CLOEXEC)` 사용. minishell에서는 보통 execve 전 명시적으로 닫습니다.

### 파이프라인에서의 fd 관리 (핵심 패턴)

```c
int pipefd[2];
pipe(pipefd);  /* pipefd[0] = read, pipefd[1] = write */

pid_t left = fork();
if (left == 0)
{
    dup2(pipefd[1], STDOUT_FILENO);  /* 왼쪽의 stdout → pipe write */
    close(pipefd[0]);                /* 왼쪽은 read 끝이 필요 없음 */
    close(pipefd[1]);                /* dup2 했으니 원본도 닫음 */
    execve(...);
}

pid_t right = fork();
if (right == 0)
{
    dup2(pipefd[0], STDIN_FILENO);   /* 오른쪽의 stdin ← pipe read */
    close(pipefd[0]);
    close(pipefd[1]);
    execve(...);
}

/* 부모: 파이프 양쪽 다 닫아야 EOF가 전파됨 */
close(pipefd[0]);
close(pipefd[1]);
waitpid(left,  NULL, 0);
waitpid(right, NULL, 0);
```

**부모가 파이프를 닫지 않으면** 오른쪽 자식이 읽기 쪽에서 EOF를 영원히 받지 못해 **블록**됩니다. 이게 가장 흔한 데드락.

자세한 내용은 [05. 파이프와 IPC](05-파이프와-IPC).

## FD 저장 / 복원 패턴

리다이렉션 후 원래 stdin/stdout을 복구하고 싶을 때:

```c
int saved_stdout = dup(STDOUT_FILENO);  /* 원본 백업 */
dup2(file_fd, STDOUT_FILENO);           /* 리다이렉트 */
/* ... 명령 실행 ... */
dup2(saved_stdout, STDOUT_FILENO);      /* 복원 */
close(saved_stdout);
```

빌트인을 리다이렉션 있는 상태로 실행할 때 이 패턴이 유용합니다(fork 없이 부모 셸에서 실행해야 하므로). 빌트인 실행 전 백업, 실행 후 복원 패턴으로 구현하거나, 리다이렉션이 있을 때만 fork 하는 두 가지 접근이 흔합니다.

## 파일 디스크립터 관련 자주 하는 실수

### 1. fd 누수
`open` 한 fd를 닫지 않으면 fd 테이블이 쌓입니다. 장기 실행 셸에서 치명적. fd는 1024개 정도밖에 안 됩니다(`ulimit -n`).

### 2. `dup2` 후 원본을 닫지 않음
위 예제처럼 `dup2(fd, 1)` 한 뒤 원본 `fd` 는 **반드시** 닫아야 합니다. 안 닫으면 자식에 쓸데없는 fd가 넘어갑니다.

### 3. `close()` 반환값 무시
대부분 문제 없지만, 네트워크 소켓 등에서는 `close` 가 실패할 수 있습니다. 셸 구현에서는 크게 신경 쓰지 않아도 됩니다.

### 4. 이미 닫힌 fd에 `close` 호출
더블 close는 `-1` 리턴만 하고 크래시는 안 나지만, 그 사이에 다른 스레드/시그널 핸들러가 같은 번호로 새 fd를 열었다면 **그걸 닫아버리는** 버그가 생깁니다. 한 번 닫았으면 변수를 `-1` 로 표시해두기.

### 5. `read` / `write` 반환값 무시
`-1` 은 에러고, `0` 은 EOF(read 에서). 짧은 read는 거의 일어나지 않지만 대비해 두면 안전.
