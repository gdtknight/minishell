# 02. 셸의 기초

## 셸이란 무엇인가

**셸(shell)** 은 사용자와 운영체제 커널 사이에서 **명령을 해석해 실행해주는 프로그램**입니다. 이름 그대로 "껍데기"처럼 커널을 감싸는 인터페이스 역할을 합니다.

```
┌─────────────┐
│   사용자    │  타이핑
└──────┬──────┘
       │
       v
┌─────────────┐
│    셸       │  문자열을 해석하여 명령을 실행
│  (bash 등)  │
└──────┬──────┘
       │ fork/execve/pipe/dup2/...
       v
┌─────────────┐
│    커널     │  실제 프로세스·파일·시그널 관리
└─────────────┘
```

셸은 단순한 "명령 실행기"가 아닙니다. 다음과 같은 일을 합니다.

1. **명령 인터프리터**: `ls -l`, `cat file.txt | wc -l` 같은 문자열을 토큰으로 쪼개고 의미를 해석.
2. **프로세스 관리자**: `fork()`로 자식 프로세스를 만들고, `execve()`로 원하는 프로그램을 실행.
3. **파이프·리다이렉션 설정자**: 프로세스 실행 전 파일 디스크립터를 정렬(`<`, `>`, `|`).
4. **환경 관리자**: 환경 변수 설정·조회(`export`, `$VAR`).
5. **제어 흐름 제공자**: 조건부 실행(`&&`, `||`), 순차 실행(`;`), 백그라운드(`&`) 등.

## 대화형 셸 vs 비대화형 셸

셸은 두 가지 모드로 동작합니다.

### 대화형(interactive) 모드
사용자가 터미널에서 직접 명령을 입력하고 응답을 받는 모드.

- **특징**: 프롬프트 표시, 히스토리, 시그널 핸들링, 라인 편집.
- **감지 방법**: `isatty(STDIN_FILENO)` 가 참.
- 보통 `readline()` 은 이 모드에서만 사용.

### 비대화형(non-interactive) 모드
- 스크립트 파일을 읽거나 파이프로 명령을 받는 모드.
- 프롬프트도 히스토리도 필요 없음.
- 직접 만든 `read` 기반 라인 리더(예: `get_next_line`)로 한 줄씩 읽음.

```sh
./myshell                      # 대화형
./myshell < script.sh          # 비대화형: stdin이 파일
echo "ls" | ./myshell          # 비대화형: stdin이 파이프
```

입력을 읽기 전에 `isatty()` 로 이 둘을 구분하고, 대화형일 때만 readline/프롬프트/히스토리를 쓰는 것이 표준 패턴입니다.

## REPL 구조

대화형 셸의 본체는 **REPL(Read-Eval-Print Loop)** 패턴입니다.

```
while (!exit_requested):
    line = read_input()       # Read
    tokens = tokenize(line)
    ast = parse(tokens)        # (파싱도 Eval의 일부로 봄)
    status = evaluate(ast)     # Eval
    // 출력은 각 명령이 직접 write()
```

프롬프트를 출력하고, `readline()` 으로 한 줄을 받고, 이를 해석해 실행한 뒤, 다시 프롬프트로 돌아옵니다.

### 메인 루프 (개념)

```c
while (!shell->is_exit)
{
    line = readline(PROMPT);      /* 1. Read */
    if (line == NULL)              /*    EOF(Ctrl-D) */
        break;
    add_history(line);             /*    히스토리 저장 */

    tokens = tokenize(line);       /* 2. Lex */
    ast = parse(tokens);           /* 3. Parse → AST */
    collect_heredocs(ast);         /* 4. heredoc 본문 선수집 */
    eval(ast);                     /* 5. Eval */

    free_line_scratch();           /*    한 줄 메모리 해제 */
}
```

## 명령의 분류

셸이 받는 명령은 크게 세 종류입니다.

### 1. 단순 명령 (simple command)
`ls -l /tmp` 같이 하나의 명령과 인자들.

### 2. 복합 명령 (compound command)
- **파이프라인**: `cmd1 | cmd2 | cmd3`
- **리스트**: `cmd1 ; cmd2`, `cmd1 && cmd2`, `cmd1 || cmd2`
- **서브셸**: `(cmd1; cmd2)` — 별도 환경에서 실행(보너스)
- **제어 구조**: `if`, `while`, `for` — minishell은 구현 안 함

### 3. 빌트인 (builtin)
셸 내부에 구현된 명령. 외부 프로그램처럼 `fork/exec`로 실행되지 않습니다.

왜 빌트인이 필요한가? 다음 명령들은 **반드시 셸의 현재 프로세스에서 실행돼야** 의미가 있습니다.

- `cd`: 자식 프로세스에서 `chdir()` 해봐야 부모 셸의 cwd는 바뀌지 않음.
- `export` / `unset`: 자식에서 환경 변수를 바꿔도 부모 셸에 영향 없음.
- `exit`: 셸 자체를 종료해야 하므로 fork하면 안 됨.

반면 `echo`, `pwd`, `env`는 기술적으로 외부 바이너리(`/usr/bin/echo` 등)로도 존재하지만, **속도와 일관성**을 위해 빌트인으로 제공합니다.

## 환경과 상태

셸은 다음 **상태(state)** 를 관리합니다.

| 상태 | 설명 | 일반적인 저장 방식 |
|------|------|-------------------|
| 환경 변수 | `PATH`, `HOME`, `PWD` 등 | 해시맵 또는 정렬된 배열 |
| 마지막 종료 코드 | `$?`가 가리키는 값 | 단일 `int` |
| 현재 디렉터리 | `getcwd()` / `$PWD` | OS가 관리, 셸은 `PWD`만 동기화 |
| 히스토리 | 이전에 입력한 명령들 | readline 내부 |
| 셸 옵션 | set -e, -x 등 (minishell 미구현) | — |

## 상태 관리 패턴

셸 구현에서 자주 쓰이는 두 가지 패턴.

### 1. 상태 객체 전파 (파라미터 패싱)

명령 평가 함수들이 상태 구조체의 포인터를 인자로 받아 전달. 테스트 용이, 의존성 명시적.

```c
int eval(t_shell *sh, t_ast *node);
int eval_command(t_shell *sh, t_ast *node);
```

### 2. 함수-로컬 `static` 싱글톤 (게터 경유)

전역 변수 선언 없이 `static` 으로 유지된 인스턴스를 포인터로 돌려주는 패턴. 42 의 "전역 변수 금지" 조항을 우회하기 좋습니다.

```c
t_shell *get_shell(void)
{
    static t_shell shell;
    return &shell;
}
```

**환경 변수 저장**: 문자열 배열(`char **envp`) 은 조회·수정이 O(n) 이라 셸 내부에서는 해시맵이나 정렬된 이중 연결 리스트로 유지하고, `execve()` 직전에만 `char **` 로 재조립하는 게 흔합니다.

## bash를 기준으로 한다

서브젝트:
> If you have any doubt about a requirement, take bash as a reference.

애매한 동작은 bash와 맞추면 됩니다. 실제로 헷갈릴 때는 bash에서 직접 돌려보고 출력·종료 코드를 비교합니다.

```sh
bash -c 'echo $?'         # 기대 동작 확인
echo $?                   # 내 셸에서 확인
```
