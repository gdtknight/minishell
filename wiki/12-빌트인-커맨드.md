# 12. 빌트인 커맨드

## 왜 빌트인인가

**빌트인(builtin)** 은 셸 바이너리 안에 직접 구현된 명령으로, **fork/exec 없이** 셸 프로세스 자체에서 실행됩니다. 빌트인이 아니라면 외부 프로그램(`/usr/bin/cd` 같은) 이 될 텐데, 그러면 다음 문제가 생깁니다.

```sh
cd /tmp          # 자식에서 chdir() 해봐야 부모 셸의 cwd 는 그대로
```

자식 프로세스에서 `chdir()` 을 해도 **부모 셸의 cwd 는 바뀌지 않습니다**. 환경 변수·현재 디렉터리·셸 종료 같은 것은 **부모 셸 자체의 상태를 바꿔야** 의미가 있어 빌트인이어야 합니다.

서브젝트가 요구하는 7개:

1. `echo` (`-n` 옵션만)
2. `cd`
3. `pwd`
4. `export`
5. `unset`
6. `env`
7. `exit`

## echo

### 동작

```sh
echo hello world
# hello world

echo -n "no newline"
# no newline     ← 개행 없음

echo -nnnn hello    # bash: -n 만 반복된 옵션은 그냥 -n 으로 인식
# hello
```

### 구현

```c
t_status	builtin_echo(char **args)
{
    int i = 1;
    int no_newline = 0;

    /* -n, -nn, -nnn 등을 모두 옵션으로 인정 */
    while (args[i] && is_n_option(args[i]))
    {
        no_newline = 1;
        i++;
    }

    while (args[i])
    {
        ft_putstr_fd(args[i], STDOUT_FILENO);
        if (args[i + 1])
            write(STDOUT_FILENO, " ", 1);
        i++;
    }
    if (!no_newline)
        write(STDOUT_FILENO, "\n", 1);
    return SUCCESS;
}

static int	is_n_option(const char *s)
{
    int i = 1;
    if (s[0] != '-' || !s[1]) return 0;
    while (s[i] == 'n') i++;
    return (s[i] == '\0');
}
```

### 주의

- 인자 사이 **단일 공백**.
- `-e`, `-E` 는 요구 안 함 (bash 에는 있지만).
- 인자 0개: 그냥 개행만.

## cd

### 동작

```sh
cd /tmp           # 절대 경로
cd ..             # 상대 경로
cd                # 인자 없음 → $HOME 으로
cd -              # $OLDPWD 로 (이전 디렉터리)
cd --             # $HOME 으로 (bash)
```

`$OLDPWD`, `$PWD` 환경 변수를 업데이트해야 합니다.

### 알고리즘

```c
t_status	builtin_cd(char **args)
{
    char *target;

    if (count_argc(args) > 2)
    {
        ft_putstr_fd("minishell: cd: too many arguments\n", STDERR_FILENO);
        return FAILURE;
    }
    if (!args[1] || ft_strncmp(args[1], "--", 3) == 0)
        target = get_value(envp_map, "HOME");
    else if (ft_strncmp(args[1], "-", 2) == 0)
    {
        target = get_value(envp_map, "OLDPWD");
        ft_putendl_fd(target, STDOUT_FILENO);     /* - 는 새 경로도 출력 */
    }
    else
        target = args[1];

    if (!target)                                   /* HOME/OLDPWD 미설정 */
    {
        ft_putstr_fd("minishell: cd: HOME not set\n", STDERR_FILENO);
        return FAILURE;
    }
    if (chdir(target) == -1)
    {
        perror(target);
        return FAILURE;
    }
    update_pwd();   /* OLDPWD = PWD, PWD = getcwd() */
    return SUCCESS;
}
```

### `update_pwd()`

```c
void	update_pwd(void)
{
    char cwd[PATH_MAX];
    char *old_pwd = get_value(envp_map, "PWD");

    if (old_pwd)
        put_key_value(envp_map, "OLDPWD", old_pwd);
    if (getcwd(cwd, sizeof(cwd)))
        put_key_value(envp_map, "PWD", cwd);
}
```

### 에러 처리

- 인자가 2개 이상: `cd: too many arguments`
- `$HOME` 미설정: `cd: HOME not set`
- `$OLDPWD` 미설정: `cd: OLDPWD not set`
- 존재하지 않는 디렉터리: `cd: /foo: No such file or directory` (perror)
- 파일인데 디렉터리 아닌 경우: `cd: /etc/hosts: Not a directory`
- 권한 없음: `cd: /root: Permission denied`

## pwd

### 동작

```sh
pwd
# /home/yoshin/work
```

### 구현

```c
t_status	builtin_pwd(char **args)
{
    char buf[PATH_MAX];
    (void)args;

    if (!getcwd(buf, sizeof(buf)))
    {
        perror("pwd");
        return FAILURE;
    }
    ft_putendl_fd(buf, STDOUT_FILENO);
    return SUCCESS;
}
```

### 주의

- `$PWD` 환경 변수를 그대로 출력할 수도 있지만, bash 의 `pwd` 는 옵션에 따라 `getcwd()` 결과(`-P`, physical) 와 `PWD` 변수(`-L`, logical) 를 구분합니다. minishell 은 `getcwd()` 한 가지로 통일하면 충분.
- 옵션 없음. `-L`, `-P` 미구현.

## export

### 동작

```sh
export FOO=bar              # 설정
export FOO                  # 값 없이 선언 (bash)
export                      # 현재 export 된 변수 목록 출력 (정렬됨)
export FOO+=baz             # 이어붙이기 (bash)
```

### 이름 검증

변수 이름 규칙:
- 첫 글자: 영문자 또는 `_`
- 이후: 영문자·숫자·`_`

잘못된 이름이면 `export: '1VAR': not a valid identifier` 류 메시지 + last_status=1, 다만 다른 인자는 계속 처리.

### 구현 스케치

```c
t_status	builtin_export(char **args)
{
    int argc = count_argc(args);
    t_status status = SUCCESS;

    if (argc == 1)
    {
        print_exported_sorted();      /* declare -x KEY="VAL" 형식 */
        return SUCCESS;
    }

    for (int i = 1; args[i]; i++)
    {
        char *eq = ft_strchr(args[i], '=');
        char *key = eq ? ft_substr(args[i], 0, eq - args[i]) : ft_strdup(args[i]);
        if (!is_valid_identifier(key))
        {
            ft_putstr_fd("minishell: export: `", STDERR_FILENO);
            ft_putstr_fd(args[i], STDERR_FILENO);
            ft_putstr_fd("': not a valid identifier\n", STDERR_FILENO);
            status = FAILURE;
            free(key);
            continue;
        }
        if (eq)
            put_key_value(envp_map, key, eq + 1);
        else
            /* 값 없이 선언만 — bash 는 "export 플래그만 세팅" */
            ; /* 해시맵에 빈 값으로 넣거나, 이미 있으면 그대로 */
        free(key);
    }
    return status;
}
```

### 출력 형식

인자 없이 `export` 를 치면:

```
declare -x HOME="/home/user"
declare -x PATH="/usr/bin:/bin"
declare -x PWD="/home/user/work"
```

- **알파벳순 정렬**.
- `declare -x ` 접두어.
- 값은 큰따옴표로 감쌈.

`declare -x` 대신 `export` 접두어를 쓰는 구현도 있습니다. 서브젝트가 정확한 포맷을 요구하지 않으니 bash 출력을 참고해 비슷하게 만들면 됩니다.

## unset

### 동작

```sh
unset FOO BAR          # 환경 변수 삭제
unset 1VAR             # 유효하지 않은 이름 — 에러
```

### 구현

```c
t_status	builtin_unset(char **args)
{
    t_status status = SUCCESS;

    for (int i = 1; args[i]; i++)
    {
        if (!is_valid_identifier(args[i]))
        {
            ft_putstr_fd("minishell: unset: `", STDERR_FILENO);
            ft_putstr_fd(args[i], STDERR_FILENO);
            ft_putstr_fd("': not a valid identifier\n", STDERR_FILENO);
            status = FAILURE;
            continue;
        }
        t_hash_entry *entry = get_entry(envp_map, args[i]);
        if (entry)
            remove_entry(envp_map, entry);
    }
    return status;
}
```

### 주의

- 존재하지 않는 변수를 unset: **에러 아님**. 조용히 성공.
- 잘못된 이름: 에러.

## env

### 동작

```sh
env                  # 모든 환경 변수 출력
env | grep PATH      # 파이프 가능
```

인자·옵션 없는 경우만 구현. `env CMD` 처럼 프로그램 실행은 미구현.

### 구현

```c
t_status	builtin_env(char **args)
{
    (void)args;

    char **envp = lst_from_hashmap(envp_map);
    for (int i = 0; envp[i]; i++)
    {
        ft_putendl_fd(envp[i], STDOUT_FILENO);
        free(envp[i]);
    }
    free(envp);
    return SUCCESS;
}
```

### 주의

- **값이 세팅된 변수만** 출력. `export VAR` (값 없이) 는 env 에 안 나타남(bash 규칙).
- 순서는 **삽입 순서 또는 해시맵 순서**. bash 는 특별한 정렬 안 함.
- 인자가 있으면: `env: 'foo': No such file or directory` 스타일로 에러 — 서브젝트는 인자 없는 경우만 요구하므로 에러 처리만.

## exit

### 동작

```sh
exit           # 마지막 last_status 로 종료
exit 0         # 0 으로 종료
exit 42        # 42 로 종료
exit 256       # 0 으로 종료 (256 % 256 = 0)
exit -1        # 255 로 종료
exit abc       # 에러: numeric argument required → 종료 (status 2)
exit 1 2       # 에러: too many arguments → 종료 안 함, last_status=1
```

종료 코드는 **0~255 범위로 clamp** (`arg & 0xFF`).

### 구현

```c
t_status	builtin_exit(t_shell *sh, char **args)
{
    int argc = count_argc(args);
    long long code;

    write(STDERR_FILENO, "exit\n", 5);   /* 대화형 모드에서만 출력하는 게 깔끔 */

    if (argc == 1)
    {
        code = sh->last_status;
    }
    else if (!is_numeric(args[1]))
    {
        ft_putstr_fd("minishell: exit: ", STDERR_FILENO);
        ft_putstr_fd(args[1], STDERR_FILENO);
        ft_putstr_fd(": numeric argument required\n", STDERR_FILENO);
        code = 2;
    }
    else if (argc > 2)
    {
        ft_putstr_fd("minishell: exit: too many arguments\n", STDERR_FILENO);
        return FAILURE;    /* 종료 안 함 */
    }
    else
    {
        code = ft_atoll(args[1]);
    }

    sh->is_exit = TRUE;
    sh->last_status = (unsigned char)code;
    return SUCCESS;
}
```

### 주의

- `exit` 찍으면 bash 는 `exit` 를 **stderr 또는 stdout 에 에코**합니다(대화형 한정). minishell 도 이를 따르는 게 보통.
- 숫자 아님 + 너무 많은 인자: bash 는 **숫자 아님** 을 먼저 검출하고 즉시 종료. 너무 많은 인자는 그 다음 검출.
- **파이프라인 안의 exit** (`exit | cat`) 는 자식에서만 종료. 부모 셸은 계속.

### `is_numeric` 검사

```c
static int	is_numeric(const char *s)
{
    int i = 0;
    if (s[0] == '+' || s[0] == '-') i++;
    if (!s[i]) return 0;
    while (s[i])
    {
        if (!ft_isdigit(s[i])) return 0;
        i++;
    }
    return 1;
}
```

## 빌트인 디스패치 테이블

모든 빌트인을 한 배열에 모아 매칭:

```c
typedef struct s_builtin_entry
{
    char		*cmd_str;
    t_builtin	cmd;
}	t_builtin_entry;

static const t_builtin_entry g_builtins[] = {
    {"echo",   builtin_echo},
    {"cd",     builtin_cd},
    {"pwd",    builtin_pwd},
    {"export", builtin_export},
    {"unset",  builtin_unset},
    {"env",    builtin_env},
    {"exit",   builtin_exit},
    {NULL, NULL}
};

t_boolean	is_builtin(char *cmd)
{
    if (!cmd) return FALSE;
    for (int i = 0; g_builtins[i].cmd_str; i++)
        if (ft_strncmp(g_builtins[i].cmd_str, cmd, ft_strlen(cmd) + 1) == 0)
            return TRUE;
    return FALSE;
}

void	execute_builtin(t_shell *sh, t_cmd_form *form)
{
    for (int i = 0; g_builtins[i].cmd_str; i++)
        if (ft_strncmp(g_builtins[i].cmd_str, form->cmd, ft_strlen(form->cmd) + 1) == 0)
        {
            sh->last_status = g_builtins[i].cmd(sh, form->args);
            return;
        }
}
```

> 파일-스코프 **상수** 배열(`const`, 또는 변경되지 않는 정적 데이터)이 서브젝트 "전역 변수 1개" 룰에 걸리는지는 경계 케이스. 평가자에 따라 해석이 갈릴 수 있으니 **함수-로컬 static 으로 옮기는 편이 안전**합니다. 서브젝트 의도는 "변경 가능한 셸 상태의 전역 공유 금지".

## 자주 하는 실수

### 1. 빌트인 실행 후 last_status 업데이트 누락
각 빌트인이 `t_status` 리턴하면 평가기가 `last_status` 에 대입해야 함. 누락 시 `$?` 가 이상.

### 2. `echo` 옵션 파싱 잘못
`-nnn` 도 `-n` 으로 인정. `-n -n` 도 둘 다 옵션. 한 번 WORD 가 오면 그 뒤는 모두 출력.

### 3. `cd` 성공했는데 PWD 업데이트 안 함
`$PWD` 가 안 바뀌면 다음 명령에서 혼란.

### 4. `exit` 의 숫자 오버플로
`exit 99999999999999` 같은 거대한 값: `ft_atoll` 로 long long 한계 검사 필요. 오버플로면 bash 는 "numeric argument required" (또는 이상한 값).

### 5. `export` 로 선언만 한 변수가 `env` 에 나타남
bash 는 값이 할당된 것만 `env` 에 보여줌. `export VAR` (값 없이) 는 별도 "선언만" 상태로 관리해야 하나, minishell 은 단순화해서 값이 없으면 해시맵에 빈 문자열로 넣고 `env` 에도 빈 값으로 표시해도 무방(서브젝트 요구 밖).

### 6. 파이프라인 안에서 `cd` 가 부모 셸 디렉터리 바꿈
`echo x | cd /tmp` — "자식 프로세스 안인가" 플래그로 구분해 파이프라인 안의 빌트인은 자식에서 실행되도록.

### 7. 빌트인이 리다이렉션 적용 전에 실행됨
`echo hi > file` 에서 echo 가 리다이렉션 적용 전에 실행되면 stdout 으로 감. 적용 순서 유지.
