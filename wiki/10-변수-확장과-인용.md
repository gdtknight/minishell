# 10. 변수 확장과 인용

## 확장이란

**확장(expansion)** 은 토큰의 리터럴 문자열을 **실제 값으로 치환**하는 과정입니다. bash 는 여러 종류의 확장을 정의하는데, minishell 이 요구하는 것은:

- **매개변수 확장** (`$VAR`, `$?`) — 필수
- **틸드 확장** (`~`, `~user`) — 서브젝트 명시 없으나 일반적으로 구현
- **IFS 분할** — `$VAR` 결과에 공백이 있으면 여러 토큰으로
- **인용 제거** (quote removal) — 끝 단계에서 따옴표 문자 자체 제거

### 구현 안 해도 되는 것

- 명령 치환 `$(cmd)`, `` `cmd` ``
- 산술 치환 `$(( ... ))`
- 중괄호 확장 `{a,b,c}`
- 프로세스 치환 `<(cmd)`, `>(cmd)`
- 파일명 확장(globbing) — 보너스의 `*` 만 (bonus)

## 확장의 순서

POSIX 는 확장 순서를 엄격하게 규정합니다. 이 순서대로 해야 "`echo "$VAR"` 결과에 공백이 있어도 분할하지 않는" 같은 미묘한 동작이 맞아떨어집니다.

```
1. tilde expansion     ~, ~user → /home/user
2. parameter expansion $VAR, $?
3. (command sub)       $(cmd)          ← 미구현
4. (arithmetic sub)    $(( ... ))      ← 미구현
5. field splitting     IFS 로 분할
6. (pathname)          *.c 같은 glob   ← 보너스
7. quote removal       ', ", \ 제거
```

### 분할은 "확장 결과" 에만 적용

매우 중요한 규칙:

> IFS 분할은 **변수·치환으로 얻은 문자열**에만 적용. 원래 입력의 공백은 이미 렉서에서 분할됐음.

예시:

```sh
VAR="a  b  c"
echo $VAR       # → echo a b c    (3개의 인자)
echo "$VAR"     # → echo "a  b  c" (1개의 인자, 공백 유지)
```

`"$VAR"` 는 **인용 안의 확장** — 확장 결과가 따옴표로 감싸져 있으니 분할 안 함. 이걸 구현하려면 확장 단계에서 **어느 글자가 인용 안에 있었는지** 기억해야 합니다.

## 인용의 세 종류

| 인용 | 보호 범위 | 예외 |
|------|-----------|------|
| `'...'` (작은따옴표) | **모든** 메타문자 | 없음. 작은따옴표 안에 작은따옴표도 못 넣음 |
| `"..."` (큰따옴표) | 공백·`\|`·`<` 등 | `$VAR` 확장은 **예외적으로 수행** |
| `\` (백슬래시) | 바로 다음 1글자 | mandatory 에서는 구현 안 해도 됨 |

### 큰따옴표 안의 `$`

```sh
VAR=world
echo "hello $VAR"      # → hello world
echo "hello \$VAR"     # → hello $VAR     (백슬래시가 $ 이스케이프, bash)
echo 'hello $VAR'      # → hello $VAR     (단일 인용 — 그대로)
```

mandatory 파트는 백슬래시를 해석 안 하므로 `\$VAR` 입력이 들어오면 그냥 `\world` 가 돼도 서브젝트 관점에서는 OK.

## quote mask — 확장 구현의 핵심 아이디어

인용 안에 있던 글자와 밖에 있던 글자를 구분하려면 어떻게 할까요? **원본 value 문자열과 같은 길이의 "마스크" 문자열을 따로 둬서** 각 글자가 어떤 상태였는지 기록하는 기법이 널리 쓰입니다.

```
원본:   "hello $USER"world
        │─────────────│────│
        QUOTED        QUOTED (변수 확장 결과) + UNQUOTED
```

### 세 가지 상태

| 마스크 값 | 상수명 (예) | 의미 |
|----------|------------|------|
| `'0'` | `MASK_UNQUOTED` | 인용 밖. IFS 분할 대상 |
| `'1'` | `MASK_QUOTED`   | 인용 안. 분할 금지, 따옴표 제거 대상 |
| `'2'` | `MASK_IFS`      | IFS 문자 (분할 포인트) |

### 왜 문자 배열인가?

비트 플래그로도 가능하지만, 디버깅하면 바로 눈에 보이는 **ASCII 문자**로 구성하면 출력이 편리합니다. `printf("%s\n%s\n", value, qmask);` 로 두 줄 나란히 찍어 정렬을 확인할 수 있습니다.

### 마스크 생성

입력 문자열을 훑으면서 인용 상태에 따라 같은 길이의 마스크 문자열을 만듭니다.

```
입력:  "hello $USER"world
        ─────────────────
마스크: 111111111111100000
```

(따옴표 문자 자체도 마스크에서는 QUOTED — 어차피 나중에 quote_removal 에서 함께 사라짐)

### 쌍으로 이동 — 확장 토큰 구조체

value 와 qmask 를 한 쌍으로 묶은 구조체를 확장 중간 결과로 씁니다:

```c
typedef struct s_exp_token
{
    char	*value;
    char	*qmask;
}	t_exp_token;
```

확장의 각 단계는 이 둘을 **동시에** 수정합니다. 한쪽만 바꾸면 불일치 상태가 돼 버그.

## 매개변수 확장 — `$VAR`, `$?`, 특수 변수

### 이름 추출 규칙

`$` 뒤에 오는 변수 이름은 **영문자·언더스코어로 시작**, 이후 영문자·숫자·언더스코어.

```
$USER       → USER 변수 값
$PATH/bin   → PATH 값 + "/bin"
$123        → $1 (위치 매개변수) + "23"    ← minishell 은 $1 미지원, 그냥 빈 문자열
${VAR}      → VAR 값 (bash 문법, mandatory 는 생략 가능)
```

### 특수 매개변수

| 매개변수 | 의미 | minishell 지원? |
|---------|------|-----------------|
| `$?` | 마지막 종료 상태 | **필수** |
| `$$` | 셸 PID | 선택 |
| `$0` | 셸 이름 | 선택 |
| `$#` | 위치 매개변수 개수 | 선택 |
| `$*`, `$@` | 모든 위치 매개변수 | 선택 (보통 빈 문자열로) |
| `$!` | 마지막 백그라운드 PID | 선택 |

minishell 구현에서는 `$?` 만 필수이고 나머지는 빈 문자열로 돌려줘도 무방(서브젝트 요구사항 밖).

### 확장 예시

```
VAR=world
"hello $USER"         → "hello yoshin"
$VAR                  → "world"
hello$VAR             → "helloworld"
$?                    → "0" (직전 명령 성공 시)
$NONEXISTENT          → ""  (정의 안 된 변수는 빈 문자열)
```

### 알고리즘

```
for each WORD token:
    build qmask
    expand tilde (if applicable)
    find '$' positions
    for each $:
        if next chars are valid param name:
            extract name
            get value from env or special
            replace $NAME with value in value string
            also update qmask: value 부분을 UNQUOTED 로 (또는 상속받은 마스크로)
```

### 치환 후 qmask 업데이트 (핵심 invariant)

`$VAR` 를 확장하면 value 가 바뀌는데 qmask 도 같이 바뀌어야 합니다.

- 확장된 `$VAR` 가 **인용 밖**이었다면 → 치환된 값의 qmask 는 UNQUOTED (+ 공백은 IFS).
- 인용 안이었다면 → 치환된 값의 qmask 는 QUOTED (분할 안 됨).

이걸 놓치면 `echo "$VAR"` 이 공백 분할돼 버리는 버그. qmask 를 도입한 전체 이유가 이것을 지키기 위함이라고 봐도 됩니다.

## 틸드 확장 — `~`, `~user`

```
~           → $HOME
~/foo       → $HOME/foo
~user       → getpwnam("user")->pw_dir
~/          → $HOME/
```

규칙:

- **단어 시작 위치** 의 `~` 만 확장. `echo foo~bar` 의 `~` 는 확장 안 함.
- `~` 뒤가 문자·숫자면 사용자 이름으로 간주해 `getpwnam` 조회. 없으면 그대로.
- 큰따옴표 안의 `~` 는 확장 안 함 (bash).

`getpwnam` 은 서브젝트 허용 함수 목록에 없으므로, minishell 은 **`~user` 는 지원 안 하거나 `HOME` 만 쓰는** 간략 구현이 안전합니다.

## IFS 와 필드 분할

**IFS(Internal Field Separator)** 는 분할 구분자. 기본값은 **공백, 탭, 개행**(`" \t\n"`).

```
IFS=:
VAR="a:b:c"
set -- $VAR       # → $1=a, $2=b, $3=c
```

minishell 은 **기본 IFS 만 지원** 해도 됩니다 — `IFS=:` 같은 변경은 요구 안 함. 따라서 `" \t\n"` 하드코딩.

### 분할 알고리즘

```
split_field(value, qmask):
    result = []
    start = 0
    for i in range(len(value)):
        if qmask[i] == MASK_IFS:      /* unquoted IFS 문자 */
            if start < i:
                result.append(value[start:i])
            start = i + 1
    if start < len(value):
        result.append(value[start:])
    return result
```

중요:

- **qmask 가 IFS 이어야만** 분할 (QUOTED 문자는 건너뜀).
- 연속된 IFS 는 하나의 구분자로 취급 (빈 토큰 생성 안 함).
- 확장 결과가 빈 문자열이면 토큰 자체가 사라짐: `echo $EMPTY` → `echo` (0 인자).

## quote removal

확장이 다 끝난 마지막 단계에서 **따옴표 문자 자체를 제거**합니다.

```
value:  "hello"
qmask:  1111111
결과:   hello (따옴표 없음)
```

알고리즘:

```
for each char in value:
    if char is quote char and qmask == QUOTED:
        skip
    else:
        emit char
```

quote removal 은 **확장 파이프라인의 가장 마지막**에서 한 번만 수행.

## 전체 확장 파이프라인 (전형적)

WORD 토큰 하나를 받아 처리하는 함수의 개념적 순서:

1. **마스킹** — qmask 생성.
2. **tilde expansion** — `~`, `~user` 처리.
3. **parameter expansion** — `$VAR`, `$?` 등 치환.
4. **field splitting** — IFS 기준 분할, 결과가 여러 exp_token 리스트.
5. **quote removal** — 각 exp_token 에 적용.
6. **토큰 리스트로 재포장** — 결과 exp_token 들을 일반 토큰으로 변환해 원래 자리에 삽입.

한 번에 한 토큰씩 처리하고, 결과로 0~N개 토큰이 나올 수 있음(빈 확장은 0개, IFS 분할은 여러 개).

## 매개변수 확장 상세 예시

```
입력 원본:  echo "hi $USER"yo '$NOT' ~bob $?
```

토큰화:

```
[WORD "echo"]
[WORD "\"hi $USER\"yo"]
[WORD "'$NOT'"]
[WORD "~bob"]
[WORD "$?"]
```

각 WORD 에 대해 확장:

### `"\"hi $USER\"yo"`
- qmask: `1111111111100`  (따옴표 안 QUOTED, yo 는 UNQUOTED)
- `$USER` 확장: `"\"hi yoshin\"yo"`, qmask `1111111111111100`  (확장 부분은 상속 QUOTED)
- quote removal: `hi yoshinyo`

### `'$NOT'`
- qmask: `11111` (전부 QUOTED)
- 단일 인용 안이라 param 확장 안 함.
- quote removal: `$NOT`

### `~bob`
- 시작이 `~` 이고 뒤에 영문자 → tilde 확장.
- 결과: `/home/bob` (존재한다면), 아니면 `~bob` 그대로.

### `$?`
- 매개변수 확장 → 예: `"0"`.

최종:

```
[WORD "echo"] [WORD "hi yoshinyo"] [WORD "$NOT"] [WORD "/home/bob"] [WORD "0"]
```

## IFS 분할 예시

```
VAR="a b c"
echo $VAR
```

`$VAR` 확장 후 value=`"a b c"`, qmask=`"00000"` (모두 UNQUOTED, 공백 두 칸은 IFS).

qmask 에서 공백은 IFS(`'2'`) 로 업데이트:
```
qmask: "02020"
```

split_field 결과:
```
["a", "b", "c"]
```

따라서:
```
echo a b c     # 최종 3개 인자
```

대조:

```
echo "$VAR"
```

value=`"a b c"`, qmask=`"11111"` (전부 QUOTED). IFS 분할 안 됨.

```
echo "a b c"   # 최종 1개 인자
```

## heredoc 에서의 확장

heredoc 본문 안에서도 `$VAR` 확장이 됩니다. 단:

- **구분자가 따옴표로 감싸져 있으면** 확장 안 함.

```sh
cat << EOF
$USER          ← 확장됨
EOF

cat << "EOF"
$USER          ← 리터럴로 유지
EOF
```

구분자 토큰이 인용(따옴표 포함)을 갖고 있었는지 여부를 저장해두고, 본문 확장 루틴이 그 플래그를 보고 분기.

heredoc 의 구분자는 **따옴표 제거만** 하고 **변수 확장은 안 함**. `<< "$USER"` 라고 썼어도 구분자는 `$USER` 리터럴(따옴표 제거 후).

## 자주 하는 실수

### 1. `"$VAR"` 가 분할됨
qmask 를 유지하지 않아서 인용 안의 확장 결과도 IFS 분할되는 버그. 확장 결과 문자열의 qmask 는 "확장된 위치의 원래 qmask" 를 상속해야 함.

### 2. `$NONEXISTENT` 가 에러가 됨
정의 안 된 변수는 **빈 문자열**이어야 함. `echo $NONEXISTENT_VAR` 는 `echo` 와 동일.

### 3. `$` 자체를 변수 시작으로 인식
`$?` 다음 글자가 변수 이름의 유효 글자가 아니면 거기서 멈춰야 함. `echo $?abc` 는 `$?` 값 + `abc`.

### 4. 특수 변수를 일반 변수처럼 해시맵에서 찾기
`$?` 는 환경 변수가 아니라 셸 내부 상태. `last_status` 를 읽어야 함. 특수 변수 조회 함수를 별도로 두고, 일반 매개변수 조회보다 **먼저** 호출해 분기.

### 5. `$` 뒤에 따옴표가 오는 경우
`$"foo"` 는 bash 에서 로케일 번역 용도지만 minishell 은 무시 — `$` 그대로 + `"foo"` 로 처리.

### 6. quote removal 을 너무 일찍 수행
quote removal 은 **마지막**. 그 전에 따옴표를 지우면 IFS 분할·변수 확장 경계를 잃음.

### 7. IFS 에 없는 글자로 분할
기본 IFS 는 `" \t\n"`. 콤마 같은 건 아님. `echo a,b,c` 는 하나의 인자.

### 8. 연속 IFS 가 빈 토큰을 만듦
`echo a    b` 는 2개 인자(`a`, `b`). 빈 토큰은 생성 안 됨.
