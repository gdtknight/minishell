# 14. 메모리 관리

## 서브젝트의 요구

> 힙에 할당한 모든 메모리는 **적절한 시점에 반드시 해제**되어야 하며, 메모리 누수는 허용되지 않음.

단, `readline()` 이 내부에서 내는 누수는 예외로 인정됩니다. 본인이 작성한 코드의 누수는 한 바이트도 허용 안 됩니다.

## 셸에서 누수가 나기 쉬운 지점

### 1. readline 반환값

`readline()` 은 매번 malloc 된 문자열을 리턴합니다. 루프마다 free 하지 않으면 누수.

```c
while ((line = readline("> ")) != NULL)
{
    process(line);
    free(line);      /* ← 빠뜨리면 누수 */
}
```

### 2. 토큰 리스트

각 명령마다 `tokenize_input` 이 새 토큰 리스트를 만듭니다. 평가가 끝난 후 `clear_token_lst()` 를 호출해 각 노드의 value (strdup 된 것)와 노드 자체를 해제해야 합니다.

### 3. AST 노드

`parse_input` 이 만든 `t_syntax_node` 트리는 `remove_syntax_node()` 로 재귀 해제. 유니언 필드에 따라 해제 대상이 달라지므로 타입별 분기 필요:

```c
void	remove_syntax_node(t_syntax_node *node)
{
    if (!node) return;
    if (node->type == NODE_WORD) free(node->value.word);
    else if (node->type == NODE_ASSIGN_WORD) free(node->value.assign_word);
    else if (is_binary(node->type))
    {
        remove_syntax_node(node->value.b_node.left);
        remove_syntax_node(node->value.b_node.right);
    }
    else if (node->type == NODE_SIMPLE_COMMAND)
    {
        remove_syntax_node(node->value.command.prefix);
        remove_syntax_node(node->value.command.cmd_word);
        remove_syntax_node(node->value.command.suffix);
        clear_cmd_form(&node->value.command.form);
        if (node->value.command.heredoc_fds[0] != -1)
            close(node->value.command.heredoc_fds[0]);
    }
    /* ... */
    free(node);
}
```

### 4. 환경 변수 해시맵

`export` / `unset` / `cd` 가 반복되면 해시맵 엔트리가 누적. 각 엔트리의 key/value/entry 전부 해제. 셸 종료 시 `clear_hashmap`.

### 5. 확장 중간 구조체

`t_exp_token` 은 value + qmask 두 문자열을 가짐. 각 단계에서 문자열을 새로 만들고 이전 문자열을 free 해야 함.

```c
void	replace_exp(t_exp_token *ex, size_t *idx, char **pair)
{
    char *new_value = /* 새 합성 */;
    char *new_qmask = /* 새 합성 */;
    free(ex->value);
    free(ex->qmask);
    ex->value = new_value;
    ex->qmask = new_qmask;
}
```

### 6. fork 한 자식의 메모리

자식은 부모 메모리를 복제해 가지고 있습니다. execve 로 교체되면 자동 해제되지만, execve 전에 `_exit` 으로 빠진다면 해제 의미 없음(자식 프로세스가 통째로 사라지므로). 단, 자식이 heap을 엄청 많이 할당했다면 부모 메모리의 CoW 페이지가 낭비됨 — 중요하진 않음.

### 7. execve 전 준비한 경로·envp 배열

`find_path` 가 돌려준 경로와 `lst_from_hashmap` 이 만든 envp 는 자식에서 malloc 된 메모리. execve 가 성공하면 해당 프로세스가 사라지므로 해제 의미 없음. **execve 실패 시** 해제 필요 — 보통 자식은 _exit 으로 빠지므로 안 해도 leak 는 안 생기지만, 습관적으로 해제해도 해로울 것 없음.

## double free 와 use-after-free

### double free

같은 포인터를 두 번 free 하면 크래시(glibc 가 보호하긴 함). 한 번 free 한 다음엔 포인터를 `NULL` 로 설정하는 습관:

```c
free(ptr);
ptr = NULL;
```

`free(NULL)` 은 안전(아무것도 안 함).

### use-after-free

해제된 메모리를 다시 읽으면 **정의되지 않은 동작**. 보통 랜덤 데이터를 읽지만, 공격자가 그 자리에 넣어둔 값을 실행할 수도 있는 보안 취약점.

## `malloc` 실패

정상적으로는 거의 안 일어나지만, 시스템이 메모리 부족이면 `malloc` 이 NULL 을 돌려줍니다. 서브젝트는 이걸 "undefined behavior" 로 간주하는지 명확하지 않지만, 방어 코드를 두는 편이 안전:

```c
char *s = malloc(n);
if (!s)
{
    perror("malloc");
    clear_shell_data();
    exit(errno);
}
```

## `valgrind` 로 누수 검사

```sh
valgrind --leak-check=full \
         --show-leak-kinds=all \
         --track-origins=yes \
         --suppressions=readline.supp \
         ./minishell
```

### readline suppression 파일

readline 의 내장 누수를 무시하려면 suppression 파일을 만듭니다.

```
# readline.supp
{
   readline_alloc
   Memcheck:Leak
   ...
   obj:*libreadline*
}
{
   readline_add_history
   Memcheck:Leak
   ...
   fun:add_history
}
```

인터넷에서 `readline.supp` 템플릿을 찾아 조정.

### `--gen-suppressions=all` 옵션

한 번 돌려보고 valgrind 가 제안하는 suppression 블록을 수집해 파일로 만들 수도 있습니다.

## AddressSanitizer (선택)

gcc/clang 에 내장된 가벼운 대안. 컴파일 플래그로 활성화.

```sh
cc -fsanitize=address -g src.c
```

빠르지만 fork 와 상성이 안 좋을 수 있음(자식 죽을 때 리포트가 반복 출력). minishell 에서는 주로 valgrind.

## 메모리 관리 패턴

### 1. 소유권 규칙 정하기

함수가 포인터를 **전달받는가, 돌려주는가**. 누가 free 책임인가.

```c
/* 소유권 이동: 호출자가 free 해야 함 */
char	*make_string(void);

/* 소유권 유지: 호출자는 free 하면 안 됨 */
const char	*get_shell_name(void);

/* 함수가 내부에서 free 하고 NULL 리턴할 수도 있는 경우 */
char	*take_and_transform(char *input);
```

주석이나 헤더 주석으로 명시.

### 2. 할당·해제 쌍 함수

```c
t_token	*create_empty_token(void);   /* malloc */
void	remove_token(t_token *t);    /* free */
```

만드는 함수마다 짝이 되는 삭제 함수를 정의. 생성한 쪽이 free 책임.

### 3. 일괄 정리 함수

리스트·트리의 모든 노드를 해제하는 함수:

```c
void	clear_token_lst(t_token **lst);
void	remove_syntax_node(t_syntax_node *node);   /* 재귀 */
void	clear_hashmap(t_hash_map *map);
```

명령 한 번 실행 후 이것들을 호출하면 이번 사이클 메모리가 정리됨.

### 4. 에러 경로에서도 해제

```c
char *a = malloc(1);
char *b = malloc(1);
if (!b)
{
    free(a);        /* ← 놓치기 쉬움 */
    return (NULL);
}
```

goto 를 norm 에서 못 쓰므로, 단계별로 실패 분기하면서 누적된 할당을 모두 해제.

### 5. `atexit` 은 쓰지 말자

표준 라이브러리의 `atexit` 는 허용 함수에 없음. 종료 전 정리는 명시적으로.

## 셸에서 흔한 메모리 해제 지점

### 매 명령 실행 후

하나의 "라인 스크래치 정리" 함수로 다음을 일괄 해제하는 것이 깔끔:

- input_line (readline 리턴값) free
- 토큰 리스트 전부 해제
- AST 재귀 해제

이걸 메인 루프의 매 반복 끝에 한 번씩 부르면 각 명령 실행마다 누수 0 유지.

### 셸 종료 시

종료 직전 호출하는 "셸 데이터 정리" 함수로:

- 환경 변수 저장소(해시맵 등) 해제
- 저장된 기타 상태 리소스

### heredoc fd

heredoc 파이프의 read 끝은 사용 후 반드시 close. 명령이 fork 후 자식으로 들어가면 자식에서 dup2 후 close 해야 함(부모도 close).

## 자주 하는 실수

### 1. readline 리턴값 free 안 함
매 루프 free 빠지면 누수.

### 2. 토큰 value 는 해제하고 토큰 노드는 안 함
구조체 free 도 빠뜨리지 말 것. 또는 그 반대(노드는 해제했는데 value 누수).

### 3. `strdup`/`ft_strdup` 결과를 함수 안에서 버림
리턴 후 호출자가 받지 않으면 leak. 소유권 체인 확인.

### 4. 2차원 배열 (`char **`) 해제 누락
`args` 같은 NULL 종료 배열은 각 문자열 + 배열 자체 모두 free.

```c
void	free_arr(char **arr)
{
    int i = 0;
    while (arr && arr[i])
    {
        free(arr[i]);
        i++;
    }
    free(arr);
}
```

### 5. heredoc 본문 문자열 누수
수집 후 `io_target` 에 저장한 본문은 AST 삭제 시 해제돼야 함. `remove_syntax_node` 에서 타입 분기 확인.

### 6. 파이프 fd 누수
`pipe()` 로 만든 두 fd 를 어느 프로세스에서도 close 안 하면 fd 테이블 누수(fd limit 도달). 프로세스 종료 시 OS 가 정리해주지만, 장기 실행 중에 누적되면 한계 도달.

### 7. `exit()` 전에 정리 안 함
빌트인 `exit` 은 `is_exit = TRUE` 플래그만 세팅하고 메인 루프로 돌아가서 정상 경로로 종료해야, 일괄 해제가 돌아감. 즉시 `exit()` 불러버리면 많은 메모리 leak.

### 8. fork 후 부모에서 자식용 메모리 free
파이프라인 fork 후 부모가 자식이 쓸 데이터를 free 해버리면 자식은 이미 복제본을 갖고 있어 문제없긴 하지만, 부모 자신이 해당 포인터를 이후 참조하지 않도록 관리.
